A rule that checks whether a vehicle exists has loaded the vehicle by the time it passes, and the method that renames the vehicle needs it too.
A value rule leaves the vehicle for the rules that require it and for the method, so that neither loads it again.

The bean reads as the link:{javadoc-core}/Checked.html[`Checked`] that a check returns without Spring: `hasValue` tells whether a value rule that does not always apply ran, and a method that takes a collection reads the value of an element with `values.element(i).valueOf(...)`.

== Where the values are

The values belong to one call of the method, on the thread that calls it, while it runs:

* What the method calls on that thread reads them too, such as a helper of the service.
* An advised method that it calls reads its own values until it returns, and then the method reads its own again. An advised method whose rules leave no value has none to read, not those of the method that called it.
* They are not there while the rules are checked, before the check, after the method returns, or on any other thread, such as in an `@Async` method that the method calls: reading them there fails with an `IllegalStateException` that says so. Pass the value itself to such code.
An `@Async` method with rules checks them on the thread that runs it, as xref:spring/transactions.adoc#_other_advice[Other advice] describes, and reads its own values there.
* A check that fails leaves no values: it throws, and the method does not run.

A rule reads the values of the rules it requires from its context, not from the bean.

== Testing a method that reads values
