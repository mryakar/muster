= Testing
:description: How to test business rules and the code around them in a Spring Boot application: a rule on its own, a rule against the database, and the web layer.

== A rule on its own

A rule is a plain object, and a test that needs nothing of Spring creates it and calls `check`, as xref:core/rules.adoc#_testing_a_rule[Testing a rule] shows.

== A rule against the database

A rule that queries the database is tested against it, with a slice of the application that has the database and the repository, and no web layer:

----
include::example$spring-boot-test/java/example/spring/VehicleNameUniqueTest.java[tag=jdbc-test,indent=0]
----

`@JdbcTest` starts the embedded database with the schema of the application, and rolls back after each test.

== The web layer

A `@WebMvcTest` brings in the starter's answer to violations and its message resolver, and nothing that checks rules: a service imported into the slice would check none.
A test of a controller makes the mocked service throw the violation it wants to see answered:

[source,java]
----
include::example$spring-boot-test/java/example/spring/VehicleControllerTest.java[tag=web-mvc-test,indent=0]
----

The answer is the one a client gets, with its message from the message source of the application.

== The whole application

A test that starts the whole application, such as with `@SpringBootTest`, checks the rules as production does: the example itself starts, calls its own endpoints over HTTP, and compares the answers with those this guide shows.
