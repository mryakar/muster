= Testing
:description: How to test business rules and the code around them in a Spring Boot application: a rule on its own, a rule against the database, and the web layer.

== Test dependencies

Spring Boot 4 puts the test slices of each module in a test starter of its own, such as these for the slices of this page:

[source,kotlin]
----
testImplementation("org.springframework.boot:spring-boot-starter-jdbc-test")
testImplementation("org.springframework.boot:spring-boot-starter-webmvc-test")
testImplementation("org.springframework.boot:spring-boot-starter-security-test")
----

The last one brings `@WithMockUser`, which the test of the web layer uses for its caller.
The slices moved to packages of those modules, as the imports of the examples show.

== A rule on its own

A rule is a plain object, and a test that needs nothing of Spring creates it and calls `check`, as xref:core/rules.adoc#_testing_a_rule[Testing a rule] shows.

== The web layer

== The whole application

A test that starts the whole application, such as with `@SpringBootTest`, checks the rules as production does: the example itself starts, calls its own endpoints over HTTP, and compares the answers with those this guide shows.
A method that reads the values of its rules needs that application too, as xref:spring/values.adoc#testing[Testing a method that reads values] shows.

== The starter's configuration

A test of how the application configures the starter, such as with `muster.self-invocation`, needs neither a database nor a web layer: Spring Boot's `ApplicationContextRunner` starts a context with `AutoConfigurations.of(MusterAutoConfiguration.class)` and the beans of the test, and asserts that it starts, or fails with the message the application would.
