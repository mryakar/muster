= Muster
:description: Business rules for layered Java applications, checked before the service method runs: inside the transaction, outside the service code.

Does your request pass muster?

Service methods tend to start with a wall of checks: does this record exist, is that name already taken, is the task in the right state.
Muster moves each of those checks into its own rule class.
With the Spring Boot starter, rules run before the first line of the service method, inside its transaction, so adding a rule never means editing the service, and a violated rule reaches the client as problem details in its language.

Format checks on a single field, such as blank, negative or malformed, stay with Jakarta Bean Validation.
Muster is for rules that need the database and the context of the operation.

== Installation

Muster is on Maven Central.
Import the BOM, which keeps the versions of the Muster modules in line, and add the Spring Boot starter, or the core alone without Spring, without a version.

Gradle:

[source,kotlin,subs="+attributes"]
----
dependencies {
  implementation(platform("me.yakar.muster:muster-bom:{muster-version}"))
  implementation("me.yakar.muster:muster-spring-boot-starter") // or muster-core without Spring
}
----

Maven:

[source,xml,subs="+attributes"]
----
<dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>me.yakar.muster</groupId>
      <artifactId>muster-bom</artifactId>
      <version>{muster-version}</version>
      <type>pom</type>
      <scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>

<dependencies>
  <dependency>
    <groupId>me.yakar.muster</groupId>
    <artifactId>muster-spring-boot-starter</artifactId> <!-- or muster-core without Spring -->
  </dependency>
</dependencies>
----

Muster needs Java 21 or later, and the starter Spring Boot 4.0.9 or later.
The core is the Java module `me.yakar.muster`; used without Maven or Gradle, it also needs `org.jspecify:jspecify` to compile.
Releases are signed; https://github.com/mryakar/muster/blob/main/SECURITY.md#verifying-a-release[SECURITY.md] says how to verify them.
