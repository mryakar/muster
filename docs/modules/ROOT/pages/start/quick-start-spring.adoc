= Quick start with Spring Boot
:description: A first business rule in a Spring Boot application in four steps: a rule class, a command, a service method, and the message the client reads, with no call to Muster in the service.
include::partial$javadoc.adoc[]

This page adds a business rule to a Spring Boot application, in four small steps.
You need Java 21 or later and Spring Boot 4.0.9 or later.
The example keeps its vehicles in a database, as most Spring Boot applications do; Muster itself needs none.
xref:start/concepts.adoc[] explains every word used here; xref:start/quick-start-java.adoc[the quick start without Spring] shows what happens underneath.

The application keeps the vehicles of a fleet, and the rule is: two vehicles must not have the same name.
Every sample on this page is part of an example application that runs on every build of Muster, calls itself over HTTP, and fails if an answer is not the one this page shows.

== Step 1: add the starter

Add the Spring Boot starter of Muster to your build, as xref:index.adoc#_installation[the home page] shows: the BOM, and `muster-spring-boot-starter` without a version.
There is nothing to configure: the starter switches itself on.

----
include::example$spring-boot/java/example/spring/VehicleNameUnique.java[tag=rule,indent=0]

Read it from the top:

* link:{javadoc-core}/rule/Rule.html[`@Rule(id = "vehicle.name-unique")`] gives the rule its id; the client receives it as the code of the violation.
* link:{javadoc-core}/rule/BusinessRule.html[`implements BusinessRule<VehicleFields>`] says which input it checks: anything that carries the fields of a vehicle.
* The starter finds rule classes in the packages of your application, as Spring Boot finds entities, and creates each one as a bean.
So the rule needs no `@Component`, and gets the repository through its constructor, like any other bean.
* `check` asks the repository, and answers `passed()`, or a violation that names the field (`name`), the value a message needs, and the kind of problem: link:{javadoc-core}/rule/Category.html[`CONFLICT`], which becomes HTTP status 409.

One rule object serves every call, from every thread, as any singleton bean does.
It does not lock what it reads, so two clients who pick the same name at the same moment can both pass it; the unique constraint of the table stays the last guard, as xref:spring/transactions.adoc[] explains.

There is no call to Muster in it.
The constructor, left out here, takes the repository; `owner()` reads the signed-in user from Spring Security, a choice of the example that Muster does not need.
A public method of a `@Service` that takes a rule target runs the rules of that target *before its first line*, *inside its transaction*.
If a rule fails, the method does not run, and nothing is written.
Adding a rule for vehicles later adds a class, and no line to the service.

`@Validated` on the class and `@Valid` on the parameter run Jakarta Bean Validation, which needs `spring-boot-starter-validation`.
Format checks of one field, such as `@NotBlank` on the command, stay there, and run before the rules.

== Try it

The fleet has a vehicle named Ilgaz already, and names are compared whatever their case.
A client, signed in as ece, asks in Turkish for one more vehicle named ilgaz (the example application signs its users in with Spring Security; the sign-in header is left out here):

Accept-Language: tr-TR
Content-Type: application/json

{"name": "ilgaz", "plate": "06 ANK 43"}

* `message` is in the language the client asked for.
* `target` tells a form which field to mark.
* `code` lets a client react to one rule in its own code, whatever the language.

== What happened, in short

. You wrote the condition as a small class with an id; the starter found it and made it a bean.
. The command said it is a rule target; the service method said nothing at all.
. When the method was called, the starter ran the rule inside the transaction, before the method; the rule failed, and the method never ran.
. The starter turned the violation into an HTTP answer, with a message in the client's language.
